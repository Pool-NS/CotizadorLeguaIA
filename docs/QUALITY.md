# Calidad del producto y proceso

`qa/iso25010/` describe evaluación basada en ISO/IEC 25010:2023, no aprobación. ISO define un modelo de calidad de producto con características y subcaracterísticas para especificar, medir y evaluar software; no es una lista automática de cumplimiento ni una certificación del proyecto ([ficha oficial ISO/IEC 25010:2023](https://www.iso.org/standard/78176.html)). `qa/square/` usa SQuaRE como vocabulario/marco, no certificación. `qa/iso9001/` documenta prácticas de gestión de calidad; no afirma certificación. `qa/clean_code/` registra revisión de código.

Los selectores de material/medida, las reglas exactas de precio y el evaluador de stock deben mantenerse separados: la IA solo interpreta la solicitud, y faltantes o consumo real solo se declaran con recetas e inventario validados por el responsable. Las tarifas y reglas de la demo de 200 registros son explícitamente ficticias. Los apuntes fotografiados no se trataron como precios aprobados por la lectura dudosa de varias asociaciones entre medida y precio.

SonarQube está preparado como configuración Gradle. Un Quality Gate solo puede informarse tras ejecutar el análisis contra una instancia disponible con el proyecto y credenciales configurados. Compilar, ejecutar pruebas o usar ISO como referencia no significa haber pasado un Quality Gate ni estar certificado. El análisis de Cronbach/SmartPLS corresponde al instrumento y datos de investigación, no al control de calidad del código.
